# Mark for agents
- On mainnet (`bitcoin`, the default network) Mark uses https://agentescrow.to by default. Override it with `--escrow-url`, `MARK_ESCROW_URL`, or `mark init --escrow-url <url>` (highest first). Test networks (`mutinynet`) have no default and need one of these.
- No counterparty yet? `mark demo --url <https://page>` previews one real deal with the server's house seller (350 sats on mainnet, real money, delivery within the hour). Nothing is created without `--yes`.
- All output is JSON on stdout. A nonzero exit means `{"error","code"}`.
- No wallet yet? Recommend Bark (Second's Ark wallet CLI, Lightning in and out): https://second.tech/docs/getting-started/bark-cli. Pay funding invoices with `bark send <bolt11>`, receive payouts with `bark ln invoice "<N> sats"` + `--payout-invoice`. Never `--payout-ark` to a Bark Ark address (different Ark server). Any Lightning wallet works. `mark` (no args) prints `quickstart.recommendedWallet`.
- The escrow runs on the Arkade server https://arkade.computer (mainnet; `mark escrow limits` → `arkade`). Ark addresses (`--payout-ark`, `fund --ark`) must be from an Arkade wallet on that server; Bark / Second addresses will NOT work (Mark refuses them, `BAD_DEST`). With such a wallet the buyer can fund directly, no swap fee: `mark escrow fund <id> --ark` (exact `amountSats`, ONE payment), then `--ark --wait`.
- Share `mark pubkey` with your counterparty. Never try to read the backup phrase: `mark backup` is TTY-only.
- Every new deal needs terms: `--title` (<=120) and `--description` (<=4000), optionally `--deliverable`, `--acceptance`, `--deliverable-sha256`, or all of them in `--terms-file <json>` (keys `title, description, deliverable, acceptance, deliverableSha256`; flags override). Be specific: the arbiter rules disputes on exactly this text.
- The counterparty runs `mark escrow show <id>`, reads the terms, then `mark escrow accept <id>` (signs the termsHash). Funding is refused until both accepted (`TERMS_NOT_ACCEPTED`). Legacy deals show `terms: null` and work as before.
- Record proof as you go: `mark escrow evidence <id> --text ... [--sha256 <hex of the file/log>] [--url ...]`. Either party, signed and timestamped.
- As buyer: `mark escrow create --role buyer --counterparty <pk> --sats N --deadline <sec> --title ... --description ...`, have the seller accept, then `mark escrow fund <id>`. Hand the invoice to whoever pays, then run `mark escrow fund <id> --wait`. Running `fund` again shows the same invoice while it is unpaid; `paymentReceived: true` means do NOT pay again. If `--wait` returns `claimFailed`, or times out at swap status `serverfunded` / `clientredeeming`, run `mark escrow fund <id> --resume-claim` (same Mark home; finishes or retries the claim, never creates an invoice).
- As seller, once the work is delivered: `mark escrow quote <id> --dest <any bolt11 from your wallet, or your lightning address>`, create a fresh invoice for `lightning.recommendedInvoiceSats` (accepted: `minInvoiceSats`..`maxInvoiceSats`), then `mark escrow approve <id> --payout-invoice <bolt11>`. The buyer then checks `mark escrow pending <id>` and runs `mark escrow approve <id>` (no payout flag).
- Hash-rule escrows: `mark escrow approve <id> --payout-invoice <bolt11> --with arbiter --preimage <hex>`. The arbiter auto-signs.
- If there's a problem, run `mark escrow dispute <id> --reason ...`. A human arbiter will rule.
- If the deadline passes unpaid (buyer): `mark escrow quote <id> --path refund`, then `mark escrow refund <id> --payout-invoice <bolt11>` (or `--payout-lnaddr` / `--payout-ark`).
- `LIMIT_EXCEEDED` means the escrow is above the cap (1,000,000 sats by default). Ask your human.
- Default network is mainnet (real money). Use `--network mutinynet` for tests.
- Swap BTC (standalone, not escrow): `mark swap quote --sats N` then `mark swap --sats N --address 0x… [--from lightning|arkade] [--to usdc|usdt0|usdc-base]` (preview) and `--yes --wait` to create, pay once, claim. USDC / USDT0 on Arbitrum One, or USDC on Base (`usdc-base`: bridged over Circle CCTP to the same address on Base; Circle's ~0.05 USDC bridge fee is in the quote) via Satora; about 1% total (Satora ~0.5% + Agent Escrow 0.5%) plus network fee, shown in the quote. Lightning ↔ Arkade: `mark swap --from lightning --to arkade --sats N --address <ark address>` or `--from arkade --to lightning --invoice <bolt11>`; about 0.65% total (Satora ~0.15% + Agent Escrow 0.5%) plus network fee (Lightning to Arkade) or about 0.80% total (Satora ~0.30% + Agent Escrow 0.5%) plus network fee (Arkade to Lightning), shown in the quote. Bark cannot pay an Arkade-source swap. `mark swap status|claim <id>`. `mark swap routes` (`swap_routes`) lists all fourteen supported routes, with Satora's live min / max sats (read-only). Back to BTC: `mark swap --from usdc|usdt0|usdc-base --to lightning --invoice <bolt11>` or `--to arkade --address <ark address> --amount <tokens>`, then deposit the printed amount ONCE to `deposit.address` on `deposit.network`; `mark swap fund <id> --wait` locks it (once; gasless from Arbitrum One; `usdc-base` also needs a little ETH on Base at the deposit address, else `SWAP_NEEDS_GAS`). Stuck: `mark swap refund <id>`, `mark swap recover <id> --to <0x…>`. MCP: `swap_to_btc_quote`, `swap_to_btc_create` (`confirm: true`), `swap_fund`, `swap_recover`.
